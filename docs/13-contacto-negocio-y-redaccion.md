# Contacto, datos del negocio y borrado de imágenes publicadas

La sección **Contacto** del editor de landing guarda redes sociales y la ubicación en el borrador de `page_sections.config`. Solo pasan al sitio público al pulsar **Publicar**. Los enlaces sociales deben usar HTTPS. Para el mapa se usan dos enlaces: el de la ubicación, que se abre al pulsar, y la URL `src` de **Compartir → Incorporar un mapa** de Google Maps, que permite mostrar el mapa. Ambos son necesarios para publicar la ubicación.

`/admin/negocio` guarda el teléfono, las redes sociales del negocio y la imagen del QR de transferencia. Estos datos son independientes de las publicaciones de la landing y se guardan al pulsar **Guardar cambios**. El número usado para los pedidos por WhatsApp sigue definido por `ORDER_WHATSAPP_NUMBER`; cambiar el teléfono del negocio no cambia ese destino. El QR puede reutilizar una imagen del banco, reemplazarse o quitarse. `GET /api/business` expone estos datos para el futuro flujo público de pago manual. Aún no se debe presentar una transferencia como pagada solo por subir o mostrar un QR.

La antigua prohibición de borrar imágenes en publicaciones históricas evitaba referencias rotas. Ahora, al confirmar **Eliminar definitivamente**, la API sustituye esa imagen por `Imagen eliminada` en cada instantánea que la usa, elimina las referencias y borra el archivo. Conserva número de versión, fecha, publicador, textos y otras imágenes. Es una excepción deliberada a la inmutabilidad de las publicaciones; también afecta la versión pública actual. Las imágenes se sirven sin caché persistente para que no sigan visibles tras borrarse. Si la imagen era el QR activo, se quita también de la configuración del negocio.

Opciones de política consideradas: conservar el archivo y bloquear el borrado, eliminar las versiones históricas afectadas, o conservar las versiones y sustituir solo la imagen. Se aplica la tercera opción elegida para mantener el historial sin retener el archivo.
